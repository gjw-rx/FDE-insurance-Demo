# 能力建设顺序

路线图表达模块之间的先后依赖，不是另一份需求列表或 sprint 看板。具体范围、任务状态和验收证据只维护在对应的 OpenSpec change 中。

## 0. 工程骨架

维护 workspace、DDD 包边界、协作规范和架构图。当前已有工程骨架和设计文档，仍不包含业务 TypeScript 实现；架构图与验证证据见[架构文档](../arch/system-design.md)。

## 1. 领域与业务会话

先实现续保案件、五项必填资料、完整性和冲突校验、幂等提交规则，以及可恢复的业务 session。此阶段使用领域和应用测试验证规则，不依赖真实外部服务。

## 2. API 与工作台

建立 Fastify 用例接口与 React 工作台，串起材料状态、资料确认、会话恢复和 SSE 业务事件；先使用测试数据库及外部服务替身跑通核心用户旅程。

## 3. 外部能力接入

按独立 change 接入材料识别、保险知识库、Pi Agent 和保险公司适配器。每个适配器先通过契约测试和可控的沙箱场景验证。

## 4. 生产准备

在业务流程和外部契约稳定后补齐权限、脱敏、审计、迁移、恢复、可观测性、容量和告警，并逐步扩大保险公司覆盖。

## 推进规则

- 一次只推进一个可独立验收的 OpenSpec change。
- 上游阶段的服务端门禁、恢复机制和自动化验证完成后，再依赖它接入外部副作用。
- 路线顺序改变时更新本页；具体开发事项仍由 OpenSpec 管理。

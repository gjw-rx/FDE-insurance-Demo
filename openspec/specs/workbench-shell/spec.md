## Purpose

定义车险续保工作台首屏静态壳的可观察行为：页面区域结构（含对话输入区）、纯前端本地交互（报价信息隐藏切换、保司选择切换、对话输入区输入与文件类型限制）、桌面优先的自适应布局，以及不依赖后端服务的展示边界。

## Requirements

### Requirement: 工作台首屏区域结构

系统 SHALL 在工作台首屏按设计稿 `designs/designs/dialog/export.png` 展示四个区域：应用品牌栏、对话主区（含对话输入区）、最新报价卡片和保司设置卡片。

- 应用品牌栏 SHALL 展示品牌图形标、「AI智能车险助手」产品名、用户问候和退出入口；产品名 SHALL 仅使用「AI智能车险助手」，不额外展示其他品牌文案。
- 对话主区 SHALL 展示助手标题（头像、名称、副标题「在线为您提供专业车险报价」）、一条带时间戳的欢迎消息，以及固定在对话主区底部的对话输入区；欢迎文案 SHALL 提示用户可上传行驶证、身份证/营业执照，或直接发送车牌号/VIN 码。
- 对话输入区 SHALL 位于对话主区内容底部，保留对话主区自身的下内边距，且 SHALL NOT 与右列卡片区域重叠。
- 原型顶部的模拟浏览器工具栏（窗口控制按钮、前进/后退、编辑/设置等工具图标）SHALL NOT 出现在页面中。

#### Scenario: 页面加载完成

- **WHEN** 用户在浏览器中打开工作台首屏
- **THEN** 页面显示应用品牌栏、对话主区、最新报价卡片和保司设置卡片四个区域，对话主区底部显示对话输入区，且不包含模拟浏览器工具栏

#### Scenario: 欢迎消息内容

- **WHEN** 页面加载完成
- **THEN** 对话主区显示助手名称、副标题、带时间戳的欢迎消息气泡和对话输入区，欢迎文案包含上传材料与发送车牌号/VIN 码的提示

#### Scenario: 输入区底部对齐

- **WHEN** 视口宽度不小于 1212px 且页面加载完成
- **THEN** 对话输入区贴附在对话主区内容底部，完全位于对话主区内部，且其底边与右列卡片区域底边的距离不超过对话主区的下内边距

### Requirement: 对话输入区结构与文件类型提示

系统 SHALL 在对话主区底部提供对话输入区，包含多行文本输入框、「上传文件」入口、文件类型提示文案和发送入口。

- 文本输入框 SHALL 显示占位文案「输入您想咨询的车险问题...」。
- 「上传文件」入口 SHALL 显示回形针图标与「上传文件」文字。
- 文件类型提示文案 SHALL 为「仅支持图片、PDF」，且 SHALL 紧邻「上传文件」入口展示。
- 发送入口 SHALL 显示为圆形按钮并使用向上箭头图标。
- 对话输入区 SHALL 不改变品牌栏、最新报价卡片、保司设置卡片与欢迎消息气泡的既有展示内容。

#### Scenario: 输入区各元素展示

- **WHEN** 页面加载完成
- **THEN** 对话主区底部显示占位文案为「输入您想咨询的车险问题...」的输入框、「上传文件」按钮、文案「仅支持图片、PDF」和圆形发送按钮

#### Scenario: 其余区域展示不变

- **WHEN** 页面加载完成
- **THEN** 品牌栏、最新报价卡片、保司设置卡片与欢迎消息气泡的内容与本次变更前一致

### Requirement: 对话输入区本地交互

系统 SHALL 在浏览器本地处理文件选择与文件类型校验，并 SHALL 按 `agent-chat-streaming` capability 处理文本发送、消息追加与流式回复。系统 SHALL NOT 上传用户选择的文件。

- 文本输入框 SHALL 接受用户输入的文本；发送按钮 SHALL 在输入内容为空时处于不可用状态，在输入内容非空且没有活动 run 时处于可用状态。
- 用户点击可用的发送按钮后，输入框内容 SHALL 被清空，页面 SHALL 追加用户消息并通过业务 API 发起 Agent run；活动 run 结束前发送按钮 SHALL 保持不可用。
- 用户点击「上传文件」入口后，系统 SHALL 打开文件选择器，且选择器 SHALL 仅允许选择图片与 PDF 文件。
- 当用户选择的文件类型不是图片或 PDF 时（选择器限制被绕过的情况），系统 SHALL 拒绝该文件并展示提示文案「仅支持图片、PDF 格式的文件」，且 SHALL NOT 记录该文件。

#### Scenario: 空输入时发送不可用

- **WHEN** 输入框内容为空
- **THEN** 发送按钮处于不可用状态，用户无法触发发送

#### Scenario: 输入内容后发送并清空

- **WHEN** 用户在输入框中输入非空文本并点击发送按钮
- **THEN** 输入框内容被清空，对话区追加该用户消息，并产生一次业务 API 创建 run 请求

#### Scenario: 活动 run 期间发送不可用

- **WHEN** 当前消息对应的 Agent run 尚未进入终态
- **THEN** 发送按钮处于不可用状态，页面不产生第二个创建 run 请求

#### Scenario: 选择图片或 PDF 文件

- **WHEN** 用户点击「上传文件」入口并在文件选择器中选择一张图片或一个 PDF 文件
- **THEN** 页面不出现错误提示，也不产生上传请求或上传结果展示

#### Scenario: 选择越界类型文件

- **WHEN** 用户通过绕过选择器类型限制的方式选中一个既非图片也非 PDF 的文件
- **THEN** 页面显示提示文案「仅支持图片、PDF 格式的文件」，且该文件不被记录

#### Scenario: 输入区不发起网络请求

- **WHEN** 用户输入文本、点击发送按钮或选择文件
- **THEN** 文本发送只产生 `agent-chat-streaming` 定义的业务 API 请求，文件选择不产生任何上传请求，且页面不直接请求 `insurance-agent` 内部接口

### Requirement: 最新报价卡片信息隐藏切换

系统 SHALL 在最新报价卡片中展示车牌标签与示例报价摘要，并提供「隐藏」入口切换报价信息的可见性。

#### Scenario: 隐藏报价信息

- **WHEN** 用户点击「隐藏」入口
- **THEN** 车牌与报价摘要信息变为不可读（被遮蔽或隐藏），入口切换为「显示」

#### Scenario: 恢复显示报价信息

- **WHEN** 报价信息处于隐藏状态且用户点击「显示」入口
- **THEN** 车牌与报价摘要恢复为可读状态，入口切换回「隐藏」

### Requirement: 保司选择状态切换

系统 SHALL 在保司设置卡片中列出固定示例保司清单（中国平安保险、太平洋保险、国寿财、阳光保险），每家保司 SHALL 拥有独立的「请选择 / 已选择」状态，并允许用户点击切换。同一时刻 SHALL 至多一家保司处于「已选择」状态。

#### Scenario: 初始选择状态

- **WHEN** 页面加载完成
- **THEN** 保司清单展示四家保司及其名称、英文名与状态标签，初始已选择状态与静态示例数据一致

#### Scenario: 切换选中保司

- **WHEN** 已有一家保司处于「已选择」状态，用户点击另一家状态为「请选择」的保司条目
- **THEN** 被点击的保司状态变为「已选择」，原先「已选择」的保司变回「请选择」

#### Scenario: 取消选中一家保司

- **WHEN** 用户点击状态为「已选择」的保司条目
- **THEN** 该保司状态变回「请选择」，且不触发任何后端请求

### Requirement: 桌面优先

系统 SHALL 以原型 1212×786 桌面视口为布局基准，并在较窄桌面视口下保持内容完整可读。基准视口下对话主区 SHALL 与右列卡片等高。

#### Scenario: 基准桌面视口

- **WHEN** 视口宽度不小于 1212px
- **THEN** 页面区域按原型比例排列：对话主区居左，最新报价与保司设置卡片居右纵向排列，且对话主区与右列区域等高对齐

#### Scenario: 较窄桌面视口

- **WHEN** 视口宽度小于 1212px 但不小于 768px
- **THEN** 页面不出现横向滚动或内容重叠，卡片按可用宽度收缩或堆叠排列，所有文本保持可读

### Requirement: 无后端服务的静态展示

系统 SHALL 在后端服务不可用时仍完成工作台首屏静态区域展示，并保持报价隐藏切换、保司选择切换和文件类型校验等本地交互可用。首屏历史会话请求失败时，系统 SHALL 只在会话栏（及展开的会话面板）展示该请求的加载失败状态与重试入口，SHALL NOT 用错误状态替换、遮挡或隐藏四个区域与欢迎消息。文本消息发送依赖业务 API；API 不可用时系统 SHALL 按 `agent-chat-streaming` capability 展示发送失败，而不能导致页面崩溃或隐藏其他区域。

#### Scenario: 无后端环境打开页面

- **WHEN** 在没有运行 API 服务的环境中打开页面
- **THEN** 四个区域完整展示，报价隐藏切换、保司选择切换和文件类型校验均可用，会话栏展示自身的加载失败状态与重试入口，页面其余部分不出现请求错误

#### Scenario: 无后端环境发送文本

- **WHEN** API 服务不可用且用户发送非空文本
- **THEN** 页面保留工作台其他区域和该用户消息，显示通用发送失败提示，并允许用户再次发送

#### Scenario: 会话列表失败后重试成功

- **WHEN** 历史会话请求首次失败，用户点击会话栏的重试入口且后端已可用
- **THEN** 会话栏离开失败状态并展示当前会话标题，展开的会话面板同时展示历史会话列表，四个区域与欢迎消息自始至终保持可用

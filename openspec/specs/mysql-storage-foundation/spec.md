# mysql-storage-foundation Specification

## Purpose

为云端业务 API 定义安全、可迁移且可观测的 MySQL 存储基础，使后续业务能力能够在统一的数据连接和版本管理边界上实现持久化。

## Requirements

### Requirement: 数据库配置必须安全且可验证

系统 SHALL 仅从运行环境或 secret provider 获取 MySQL 连接信息，并在创建服务前严格校验必填项、协议、连接池边界、超时和 TLS 模式。配置错误 SHALL 以稳定、可定位但不包含连接字符串、用户名、密码或证书正文的错误拒绝启动；系统不得为云端环境提供源码内默认凭据。

#### Scenario: 使用有效云端配置

- **WHEN** 部署环境提供合法的 MySQL 连接信息、受支持的 TLS 配置和边界内的连接池参数
- **THEN** 系统完成配置校验并可创建数据库连接池，且启动摘要与普通日志不包含任何数据库凭据

#### Scenario: 缺少数据库连接信息

- **WHEN** 未提供必填的数据库连接信息
- **THEN** 系统在监听 HTTP 端口前拒绝启动，并返回只标识缺失配置字段的脱敏错误

#### Scenario: 拒绝不安全或非法配置

- **WHEN** 云端运行配置禁用所需的 TLS 校验，或连接池与超时参数超出允许边界
- **THEN** 系统在建立数据库连接前拒绝配置，并且错误中不回显配置值

### Requirement: 数据库连接具有受控生命周期

系统 SHALL 以有界连接池管理 MySQL 连接，SHALL 对连接与查询设置有限超时，并 SHALL 在进程优雅关闭时停止接收新工作后关闭连接池。数据库暂时不可达不得导致无上限重试或泄露内部网络地址。

#### Scenario: 服务正常关闭

- **WHEN** API 进程收到受支持的终止信号
- **THEN** 系统停止接收新请求、等待当前受控工作收敛并关闭数据库连接池，重复关闭不产生额外副作用

#### Scenario: 数据库连接超时

- **WHEN** MySQL 在配置的连接超时内不可达
- **THEN** 系统终止本次连接尝试并记录脱敏诊断，不进行无上限重试且不输出连接字符串

### Requirement: 存活与数据库就绪状态必须分离

系统 SHALL 保留进程存活探针，并 SHALL 提供独立的数据库就绪探针。就绪检查必须执行有界的真实数据库往返；数据库不可达或超时时 SHALL 返回不可就绪状态，而不得把该状态误报为进程死亡或返回数据库内部错误。

#### Scenario: 数据库可用时服务就绪

- **WHEN** API 进程存活且数据库在检查时限内成功响应
- **THEN** 存活探针与就绪探针均返回成功

#### Scenario: 数据库不可用时服务未就绪

- **WHEN** API 进程仍存活但数据库连接失败或检查超时
- **THEN** 存活探针继续返回成功，就绪探针返回可重试的不可就绪状态且不包含内部地址、凭据或驱动错误

### Requirement: 数据库结构必须通过版本化迁移管理

系统 SHALL 提供可重复执行、按确定顺序应用且有并发互斥保护的版本化迁移命令。迁移 SHALL 由部署发布阶段显式执行，不得由每个 API 实例在启动时隐式执行；失败的迁移 SHALL 以非零状态终止并保留不含凭据的可定位证据。任何会话业务 DDL 在生成迁移或执行数据库变更前 SHALL 经过人工 review；未经批准的候选 DDL 不得进入迁移文件或数据库。

#### Scenario: 首次应用基线迁移

- **WHEN** 发布流程对空数据库执行已通过 review 的迁移命令
- **THEN** 系统按确定顺序创建迁移元数据及 `chat_session`、`chat_message`、`chat_run` 业务表，并记录当前版本；所有表均不使用外键、不使用枚举类型与取值约束，每表字段少于 30 个且索引少于 5 个

#### Scenario: 重复执行迁移

- **WHEN** 发布流程再次对已处于最新版本的数据库执行同一迁移命令
- **THEN** 命令成功结束且不重复应用已记录的迁移

#### Scenario: 并发执行迁移

- **WHEN** 两个发布执行者同时尝试迁移同一数据库
- **THEN** 系统通过数据库级互斥保证同一时刻只有一个执行者应用迁移，另一执行者在有界等待后成功确认最新版本或明确失败

#### Scenario: 迁移失败

- **WHEN** 任一迁移无法完成
- **THEN** 迁移命令以非零状态退出、不得将该迁移记录为已完成，并输出不含数据库凭据的失败标识

#### Scenario: 未经 review 的 DDL 被阻止

- **WHEN** 实现者尝试在没有明确 review 结论的情况下生成业务迁移或执行会话 DDL
- **THEN** 工作流拒绝该操作并保留数据库结构不变

### Requirement: 受控取值必须使用逻辑枚举且保持单一来源

系统 SHALL NOT 使用 MySQL `ENUM` 类型或代码枚举类；状态、角色、标题来源等受控取值 SHALL 以逻辑枚举（字符串取值 + `VARCHAR` 列）保存。取值定义 SHALL 只有一处来源，SHALL NOT 在迁移 SQL、设计副本或测试中重复写死取值清单。应用层 SHALL 在产生数据库副作用前校验取值合法性；读取到契约外的未知取值时 SHALL 返回稳定错误并保留脱敏诊断，不得把未知取值透传给调用方。

#### Scenario: 迁移不写死取值清单

- **WHEN** 生成会话业务迁移
- **THEN** 建表语句不包含 `ENUM` 类型与取值校验约束，受控取值列只声明类型与长度，取值合法性由应用层负责

#### Scenario: 非法取值在写库前被拒绝

- **WHEN** 以契约外的取值写入状态、角色或标题来源
- **THEN** 应用层在产生任何数据库副作用之前拒绝该操作，已有记录不变

#### Scenario: 读取到未知历史取值

- **WHEN** 数据库中已存在契约外的历史取值
- **THEN** 系统返回稳定错误并记录脱敏诊断，不把未知取值作为正常结果返回

### Requirement: 数据库边界必须可通过真实 MySQL 验证

系统 SHALL 使用隔离的非生产 MySQL 实例验证连接、TLS 配置边界、参数化查询、迁移幂等、迁移互斥、会话仓储事务和连接池关闭。测试不得连接生产数据库，不得在 fixture、日志或证据中保存真实凭据。

#### Scenario: 参数化查询隔离输入

- **WHEN** 集成测试将包含 SQL 元字符的会话标题或消息作为查询参数提交
- **THEN** MySQL 将该值作为数据处理而非可执行 SQL，且测试数据库结构不被非预期修改

#### Scenario: 测试环境与生产隔离

- **WHEN** 数据库集成测试启动
- **THEN** 测试仅接受明确标识的隔离数据库配置，并在无法证明目标为非生产环境时拒绝执行破坏性准备或清理

#### Scenario: 会话事务边界

- **WHEN** 集成测试执行用户消息与 run 的幂等写入，或模拟其中一步失败
- **THEN** 成功路径只产生一组完整记录，失败路径不留下孤立消息、run 或半更新标题，重复请求不会增加记录数量

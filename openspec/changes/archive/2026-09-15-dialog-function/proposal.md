## Why

工作台首屏静态壳（`workbench-shell`，见归档 change `2026-09-15-front-init`）已实现品牌栏、对话主区、最新报价与保司设置卡片，但对话主区目前只有助手标题和一条欢迎消息，没有任何输入入口，用户无法表达咨询内容。新版设计稿 `designs/designs/dialog/export.png` 已确定对话输入区的视觉方案，需要在对话主区补上这一区域，让首屏具备完整的对话交互外观，为后续接入消息发送与材料上传（roadmap 阶段 2 剩余部分）提供 UI 基础。

## What Changes

- 在对话主区底部新增对话输入区（按设计稿 `designs/designs/dialog/export.png`）：
  - 多行文本输入框，占位文案「输入您想咨询的车险问题...」。
  - 左下「上传文件」按钮，带回形针图标。
  - 按钮右侧的文件类型提示文案「仅支持图片、PDF」。
  - 右下圆形发送按钮，带向上箭头图标。
- 输入区仅实现本地 UI 交互，不发起任何网络请求：
  - 输入框可输入文本；发送按钮在有非空内容时可用，点击后清空输入内容。
  - 「上传文件」点击打开系统文件选择器，选择器 `accept` 限制为图片与 PDF；`accept` 无法拦截的越界类型在本地校验后拒绝并给出提示文案。
  - 不做文件上传、不追加消息气泡、不调用任何接口。
- 为让输入区按设计稿贴在卡片底部，允许对 `.chat-panel` 做最小必要的布局调整（如纵向 flex 与吸底）；品牌栏、报价卡片、保司卡片、消息气泡等现有样式一律不修改。
- 图标沿用现有手写内联 SVG 方式新增，不引入依赖。

### 非目标

- 不实现消息发送、SSE、消息列表渲染或智能体回复；点击发送不产生对话内容。
- 不实现文件真实上传、文件预览、上传进度或上传结果展示；不调用任何后端接口。
- 不实现五项资料确认、真实报价获取或核保流程。
- 不修改品牌栏、最新报价卡片、保司设置卡片以及现有欢迎消息的视觉与交互。
- 不单独设计移动端布局，不新增 npm 依赖，不修改 `apps/api` 与 `packages/*`。
- logo 等既有视觉资产不在本次调整范围内。

## Capabilities

### New Capabilities

（无：本次变更扩展已有工作台首屏的对话主区，不引入新的 capability。）

### Modified Capabilities

- `workbench-shell`: 对话主区新增对话输入区（输入框、上传文件入口与文件类型限制提示、发送按钮）及其本地交互行为；首屏区域结构描述补充该区域。需求入口为 `docs/features/workbench-shell.md`。

## Impact

- 代码：`apps/web/src/app/` 新增对话输入区组件与对应内联 SVG 图标，`chat-panel.tsx` 组合该组件，`styles.css` 新增输入区样式并对 `.chat-panel` 做最小必要布局调整，`data.ts` 视需要补充输入区静态文案常量。
- 依赖：不新增运行时或开发依赖。
- 外部服务：无。所有交互停留在浏览器本地状态，不发请求。
- 测试：`tests/e2e/` 新增本 change 的 Playwright 用例，覆盖输入区结构、发送按钮可用性与清空、文件类型限制与越界拒绝。
- 文档：`docs/features/workbench-shell.md` 范围与关联入口同步；新增 `docs/testing/dialog-function.md` 测试计划；`docs/arch/` 若不涉及架构变化则仅核对，不新增图源或产物。

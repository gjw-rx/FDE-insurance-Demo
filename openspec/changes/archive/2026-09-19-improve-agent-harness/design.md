## Context

见 [proposal](./proposal.md)。项目已有大量未提交的业务实现，必须保留；Pi 配置在被忽略的 `.pi/` 内，由 `.agents` 同步，第三方 pi-lens 由 npm 管理。

## Goals / Non-Goals

目标：保留质量门禁，减少机械推理、重复提示和无证据重跑。非目标：修改业务行为、升级依赖、自动判断每次模型调用的最佳推理等级、保证具体提速百分比。

## Decisions

- `.agents/harness/` 保存可版本管理的扩展与验证脚本，安装脚本合并项目 Pi settings、调用现有同步器，不直接手改生成文件。默认 medium，显式 `harness_effort` 工具选择 low/medium/high，不覆盖用户显式选择。
- 扩展仅过滤已知工具追加的非阻断提示；原始会话保留。按工具结果 ID 保证幂等，读取后文件发生外部变化则保留未读警告；未知提示、真实错误和用户消息不删除。完整文件读/写建立版本证据，局部读取不宣称完整文件已读。
- 验证用 Node 内置模块、无 shell 管道执行固定命令；完整 stdout/stderr 写入 `.runtime/harness/`，摘要包含退出码和日志路径。指纹包含源码、测试、配置、规则和依赖锁；环境变化通过明确重试理由记录，不自动复用通过结果。
- 自建子进程组在超时或取消时定向清理，不使用 pkill；相同输入与失败指纹两次后拒绝盲目第三次执行，允许带新证据说明继续。
- 更新 AGENTS、工作流、前端规则、Apply/Propose 技能和测试模板；技术维护记录在 docs/tech/agent-harness.md。产品架构未变化，不重新渲染业务架构图。

## Risks / Trade-offs

- 提示文本可能随 pi-lens 升级改变 → 只匹配已知格式，默认保留未知文本，升级后回归。
- 项目默认 medium 不强制覆盖已恢复会话 → 明确新会话/显式工具的生效边界。
- 日志可能含测试内容 → 仅运行无敏感数据的固定测试命令，日志本地忽略且权限受限，不上传。
- 当前工作树包含其他业务改动 → 不提交，不改其 tasks；验证失败分别报告归因。

## Migration Plan

先规则与脚本，后隔离测试，再安装本机配置并使用真实 SDK 无模型请求验证扩展加载。验收后记录证据并归档；回滚项目配置使用安装备份，全局中文规则保存独立备份。

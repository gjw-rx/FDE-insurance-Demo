## Why

项目计划部署在云端，后续会话、续保案件及其他业务数据需要稳定的持久化基础；当前业务 API 仅使用进程内会话仓储，重启后数据会丢失。现阶段先建立可验证、可迁移、可安全配置的 MySQL 基础设施，避免后续业务功能各自引入不一致的数据连接和迁移方式。

## What Changes

- 为业务 API 引入 MySQL 连接、严格配置校验、连接池生命周期和优雅关闭能力。
- 建立版本化数据库迁移机制与空业务基线，支持云端部署在发布阶段显式执行迁移。
- 增加数据库就绪探针：数据库不可用时仍区分进程存活与服务就绪，且错误和日志不泄露连接凭据。
- 增加基于隔离 MySQL 实例的基础设施集成测试，验证真实连接、参数化查询、迁移幂等与资源关闭。
- 同步 API 运行说明、整体架构、MySQL 技术资料、需求入口和本 change 的测试计划。
- 明确本 change 不创建会话、续保、报价、材料等业务表，不把现有 `InMemoryChatSessionStore` 替换为数据库实现，也不改变任何公开业务 API 或业务行为。

## Capabilities

### New Capabilities

- `mysql-storage-foundation`: 定义业务 API 使用 MySQL 时的配置、连接生命周期、迁移、就绪状态与安全验证要求；对应需求入口计划为 `docs/features/mysql-storage-foundation.md`。

### Modified Capabilities

无。

## Impact

- 受影响代码：`apps/api` 的配置、组合根、基础设施持久化目录、健康检查与测试；根级验证/部署辅助配置按实现需要补充。
- 新增依赖与系统：MySQL 服务、Node.js MySQL 驱动及版本化迁移工具；所有直接依赖必须固定版本并记录在 `docs/tech/mysql.md`。
- 配置影响：云端运行环境需通过 secret 注入数据库连接信息，并配置连接/查询超时与 TLS；仓库不保存真实凭据。
- 数据影响：仅允许创建迁移工具自身的元数据和空业务基线，不写入或迁移现有聊天/续保业务数据。
- 接口影响：现有公开业务接口保持兼容；新增独立 readiness 语义，不改变 `/health/live` 的进程存活语义。

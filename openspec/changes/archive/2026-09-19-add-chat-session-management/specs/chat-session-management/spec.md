## Purpose

定义单个部署实例中聊天会话的创建、历史浏览、内容恢复与标题管理行为，使用户能够在多段 Agent 对话之间可靠切换并延续上下文。

## ADDED Requirements

### Requirement: 创建独立聊天会话

系统 SHALL 允许用户创建独立的持久聊天会话，并返回稳定的 `sessionId`、标题、创建时间和更新时间。新会话 SHALL 以“新会话”为默认标题，且在创建后立即成为可发送消息的当前会话。创建入口 SHALL 位于对话主区顶部的会话栏，并使用「新会话」文案。

#### Scenario: 成功新建会话

- **WHEN** 用户点击会话栏的「新会话」且服务端成功创建 session
- **THEN** 界面切换到标题为“新会话”、没有历史消息的新 session，会话栏标题同步更新，并可在该 session 中发送消息

#### Scenario: 新建会话失败

- **WHEN** 用户点击会话栏的「新会话」但服务端无法创建 session
- **THEN** 界面显示可感知的通用失败提示，并保留用户当前查看的会话及其消息

#### Scenario: 活动 run 期间新建会话

- **WHEN** 当前 session 的 run 尚未进入终态
- **THEN** 新建会话入口保持不可用，系统不取消或迁移该 run

### Requirement: 查看历史会话列表

系统 SHALL 按最近更新时间倒序提供部署实例内的历史会话摘要，并支持稳定的游标分页。每条摘要 SHALL 包含 `sessionId`、标题、创建时间和更新时间，不得包含消息正文或敏感材料内容。当前无登录鉴权时，列表 SHALL 被视为该部署实例全局共享数据，而非用户私有数据。

对话主区顶部 SHALL 提供会话栏展示当前会话标题与更新时间；完整列表默认收纳在会话面板中，用户展开面板后 SHALL 看到全部会话标题与当前会话标识。列表请求失败时，会话栏 SHALL 直接展示失败与重试入口，不得只在未展开的面板内提示。

#### Scenario: 加载历史会话

- **WHEN** 用户打开聊天工作台且存在历史 session
- **THEN** 会话栏显示当前会话标题，且用户展开会话面板后看到按最近更新时间倒序排列的会话标题与当前会话标识

#### Scenario: 展开与收起会话面板

- **WHEN** 用户点击会话栏的列表入口或关闭入口
- **THEN** 会话面板在展开与收起之间切换，收起后不影响当前会话的消息与发送能力

#### Scenario: 没有历史会话

- **WHEN** 用户打开聊天工作台且不存在历史 session
- **THEN** 会话栏显示尚未选择会话的提示，展开面板后显示空状态，并提供新建会话入口

#### Scenario: 加载更多历史会话

- **WHEN** 历史会话数量超过单页限制且用户请求加载下一页
- **THEN** 系统使用上一页返回的游标追加更早的会话，不重复或跳过排序未变化的条目

#### Scenario: 历史列表加载失败

- **WHEN** 历史会话请求失败
- **THEN** 会话栏显示加载失败和重试入口，展开的面板也显示同一失败状态，且不把失败误呈现为空列表

### Requirement: 恢复历史会话内容

系统 SHALL 允许用户选择历史 session，并返回该 session 已持久化的用户消息和助手消息，消息顺序与原对话一致。不存在的 session SHALL 返回稳定的未找到响应，且系统不得跨 session 混合消息。

#### Scenario: 切换到历史会话

- **WHEN** 用户从会话面板选择一个存在的历史 session
- **THEN** 界面将当前消息区替换为该 session 的已保存消息，会话栏标题同步更新，面板收起，后续消息发送到该 session

#### Scenario: 选择不存在的会话

- **WHEN** 用户请求已不存在或无效的 `sessionId`
- **THEN** 系统返回稳定的未找到响应，界面保留原当前会话并显示通用错误提示

#### Scenario: 活动 run 期间切换会话

- **WHEN** 当前 session 的 run 尚未进入终态
- **THEN** 历史会话选择入口保持不可用，系统不允许切换到其他 session

### Requirement: 首条消息自动生成会话标题

系统 SHALL 在标题仍为“新会话”的 session 首次成功接受非空用户消息时，以该消息去除首尾空白后的单行文本生成标题；标题超出允许长度时 SHALL 确定性截断。该自动命名 SHALL 与消息接受操作一致地持久化，不依赖模型生成。

#### Scenario: 首条消息更新默认标题

- **WHEN** 标题为“新会话”的 session 首次成功接受用户消息
- **THEN** 系统将规范化并截断后的消息文本保存为会话标题，历史列表与当前标题显示更新后的值

#### Scenario: 后续消息不覆盖标题

- **WHEN** session 已有自动生成或手动设置的非默认标题，且用户继续发送消息
- **THEN** 系统保持现有标题不变

#### Scenario: 消息创建失败时不改标题

- **WHEN** 首条消息未被服务端接受或未能持久化
- **THEN** session 标题保持“新会话”

### Requirement: 手动重命名会话

系统 SHALL 允许用户将 session 标题修改为去除首尾空白后的非空文本，并执行稳定的最大长度校验。重命名入口 SHALL 位于会话面板的会话条目上。重命名成功后，当前会话标题和历史列表 SHALL 一致更新；无效输入不得改变既有标题。

#### Scenario: 成功重命名

- **WHEN** 用户为存在的 session 提交长度有效的非空标题
- **THEN** 系统持久化该标题并返回更新后的会话摘要，界面同步显示新标题

#### Scenario: 拒绝空标题

- **WHEN** 用户提交空字符串或仅含空白的标题
- **THEN** 系统拒绝请求、显示可感知的校验提示，并保留原标题

#### Scenario: 重命名失败

- **WHEN** 用户提交有效标题但服务端更新失败
- **THEN** 界面显示通用失败提示并恢复原标题，不显示未持久化的新标题
